Nota sobre el cambio de escenario respecto a la captura original: la evidencia previa (julio
2026) usaba `GET /api/v1/pedidos/{id}` con un token de otro Cliente para probar control de
acceso horizontal. Esa captura no pudo reproducirse con datos frescos porque requiere un pedido
ya existente entre dos usuarios (registro → contrato → firma), que esta ventana de tiempo no
permitía recrear de punta a punta. Se sustituyó por un control de acceso vertical equivalente
(usuario sin rol/permiso de administrador contra un endpoint `@PreAuthorize` real) sobre el
mismo principio de OWASP A01: una autorización insuficiente debe responder 403, nunca 200.
